# Test Suites & Golden Fixtures

Tests are your territory end to end. The developer runs them (after every change of theirs) but does not write them. Tests exist for regression protection and to verify your own scaffolding — they are not a substitute for the developer's manual verification pass.

## Golden-fixture conformance tests (every connector)
- Fixtures: 2–3 REAL captured responses/pages/files per connector in `tests/fixtures/<connector>/`, named descriptively (`nppes_org_hit.json`, `nppes_no_results.json`, `sponsor_roster_static.html`). Sanitize secrets, keep structure authentic — never hand-invent a fixture.
- The test: run the connector's parse path over each fixture → assert output validates as the contract types (`RawDocument`, identity records, or claims), assert key extracted values match expected constants written into the test, assert graceful behavior on the "empty/miss" fixture. When a producer's output on its fixtures changes, the test fails until its `producer_version` is bumped too (engine "Claim producers and the claims door", 2026-11-05).
- **When a source changes shape in production: update the fixture to the new reality FIRST (capture a fresh real sample), watch the test fail, then fix. Fixtures track truth; commits show fixture-then-fix order.**

## Core pipeline tests (highest value in the repo)
- `verify_citations`: quote present (→ `accepted`); quote absent (→ `rejected`, `rejection_reason = quote_not_found`); whitespace/smart-quote normalization; quote spanning a line break; quote appearing twice (first offset wins); quote in tables text. Include the developer's own edge-case list — ask for it if you don't have it.
- `score_and_publish`: two independent sources → verified; same press release syndicated on two domains → counts once; a brand's site and its owner's site → one source (one voice per ownership group); buyer's and seller's releases → two sources; an article reprinting an 80+ character quote from a release → a copy, one source; two outlets describing a deal in similar but not identical words → two sources; a wire tag ("/PRNewswire/") in a reposted page → a copy; single source → reported; conflict → sources_disagree, nothing published as fact; co-investors with no stated stakes → co-owners, not a conflict; two PE firms each with a stated majority in the same year → edges `sources_disagree` but the category still PE-owned; a named seller (`owned_by` with `holding: former`) ends that seller's hop; an undated portfolio listing after a dated sale is ignored, not a restart; a stated majority in a later completed acquisition ends an earlier stated majority; category precedence (PE control beats a family co-owner; with no stated stakes, a public company beats a family; a controlling owner of unconfirmed kind gives owner type not confirmed unless confirmed PE exists); a 13G filed under Rule 13d-1(b) never makes a public company PE minority stake, a 13D does, a proxy-table row alone doesn't, and an amendment reporting 5% or less ends the hop; several paths to one PE owner give the shortest degree; a category is verified when one chain giving it is fully verified; official-filing source self-verifies; `events` row per publication; retraction end-dates without deleting claims. Edge lifecycle (2026-11-07): withdrawing a producer version retracts its claims and the edges only they supported, and re-derivation never brings a retracted edge back; 18 months unconfirmed gives `unconfirmed`, not ended, and a new confirmation returns it to `active`; a cleanly parsed Schedule missing a loan ends that edge at its period end, an unparseable one changes nothing; a completed deal turns its `pending` row `active`; `terminated` ends a pending row; closing phrases map to the expected ranges in the phrase table ("in the coming weeks" = document date plus 3 months). Category storage (2026-11-07): recomputing twice changes nothing; an owner-kind change reaches every brand beneath it; only a category or confidence change writes an events row, never a new `checked_on`; the nightly drift check finds zero differences on a correct dataset and flags a planted one. Ownership filings (2026-11-08): a joint 13G listing a fund, its GP, the firm and its parent at 10,000,000 shares each gives one 8% stake, not 32%; two funds holding different shares alone with no parent row give their sum; a 13G whose rule box can't be read never makes a public company PE minority stake; an amendment reporting 5% or less ends the hop. Last-confirmed (2026-11-12): a portfolio page (`company_site`) re-fetched unchanged with the company on it advances the edge's last-confirmed date; a 2021 deal release (`press_release`) re-fetched unchanged in 2026 leaves it at 2021, so the edge turns `unconfirmed` after 18 months; a name missing from a portfolio page, even one that lists current holdings only, never ends or unconfirms ownership.
- Registry crawler (2026-11-12, engine "Rosters, portfolio pages and the registry"): fixtures are real saved portfolio pages in `tests/fixtures/registry/` (Roark's hidden "Previous Investments" section, TSG's hidden modals, Leonard Green's text status, Golden Gate's paged listing and a detail page). The HTML text extractor keeps hidden elements' text and writes `[image: …]`, `[link: …]` and `aria-label` text in place, and never writes class names or data attributes; `registry sync` creates one entry per YAML file, sends it through the door as an intake item, writes its domains as `domain` identifier rows sourced by that item, never writes its crd or cik, and retracts a removed domain with an events row; nothing from an entry reaches the extraction prompt; `detail_links` follows matching links one level deep on the same site only; paging stops at the first page with no new items and at 50 pages; a detail page unlinked for two passes stops being fetched; newsroom releases are fetched once as `press_release` and a later pass stops at the first index page with no new release links; a `required: false` page that is blocked doesn't stop a pass from counting, a blocked required page does. Challenges: a fixture challenge page (Cloudflare "Just a moment", `cf-mitigated: challenge`; Vercel Security Checkpoint) triggers exactly one browser retry with the bot's user agent and no clicks; a page that clears is stored with the cleared challenge in `meta`; one that doesn't is `blocked`; "Sorry, you have been blocked" or a plain 403 stops all fetching from the domain; an unreadable robots.txt blocks the whole site. `site_access` changes state only on a real change and writes one `site_access_changes` row per change.
- Idempotency: re-run the same extraction/filing twice → zero duplicate claims (DB unique index holds).
- Entity resolution: exact hit, fuzzy hit above threshold, ambiguous → `ambiguous` status with candidates stored and nothing linked (ADR 0002), miss → create.

## Conventions
- pytest; httpx `TestClient` for API tests; a Postgres test database via the compose stack (no SQLite substitution — CTEs and JSONB must match production).
- Factories/helpers in `tests/factories.py`; keep tests readable as documentation of intended behavior.
- Fast suite runnable in one command (`uv run pytest`); mark slow/live-network tests so the default run stays offline against fixtures.
- Never weaken an assertion to make a test pass; if behavior legitimately changed, say so and update expected values with a comment noting why.
