# Map: Engine

Label: wayfinder:map · Tracker: local markdown (`docs/agents/issue-tracker.md`) · Charted 2026-10-26 as the API spec map · Split 2026-11-04 (ADR 0004)

## Destination

`.scratch/engine/spec.md`: a build spec for the shared evidence engine: build_roadmap.md Phases 1–5 plus on-demand research (A2), Form ADV and IRS exempt-org ingestion, and BDC loan data (the first follow-up after the chains-and-brands launch, ADR 0004). It excludes the parked local-businesses work (NPPES census, launch states, SoS and vet boards) and the deferred retirement lookup. It must be complete enough that Claude can build it end to end without asking a design question, with `docs/`, `GLOSSARY.md` and the ADRs consistent with it and with each other.

Sibling maps: [chains-and-brands](../chains-and-brands/map.md) (active product), [local-businesses](../local-businesses/map.md) (parked), [retirement](../retirement/map.md) (parked), [housing](../housing/map.md) (parked, 2026-11-07). Product maps link to engine tickets and are blocked by them where needed (`engine/NN`). Ticket numbers are unique across all the folders.

## Notes

- **Domain**: ownership-transparency evidence engine (FastAPI, Celery, Postgres, S3). Read `CLAUDE.md`, `GLOSSARY.md` and `docs/adr/` first; use glossary vocabulary in every ticket and answer.
- **Shared by both products**: an engine ticket answers for chains and brands (active) and must not close off local businesses or housing (both parked). Local-only, retirement-only or housing-only questions go to their own maps, not here (ruled 2026-11-04; housing added 2026-11-07).
- **Authorship** (decisions.md §13): the developer decides, Claude builds. Grilling tickets are HITL — never answer the developer's side.
- **Skills**: grilling tickets → `grilling` + `domain-modeling`. Extraction tickets → also `claude-api`. Stack API specifics (FastAPI, Pydantic v2, SQLAlchemy 2.0, Alembic, Celery) → Context7 (CLAUDE.md documentation rules).
- **Resolving a ticket** = `## Answer` in the ticket **plus** recording the decision where it belongs: the doc it changes, `GLOSSARY.md`, or an ADR (only when hard to reverse, surprising, and a real trade-off). Fix the doc remnants the ticket's context lists. **No application code** until the engine map and the active product map are done.
- **Research tickets**: findings go to `.scratch/engine/research/<slug>.md`, every claim cited to a primary source. No branches, commits or pushes — git commits are the developer's alone.
- **Ticket context** was captured from two inventories (open items/contradictions, and spec-coverage gaps) run 2026-10-26; line numbers may drift as docs change — search by phrase if a reference misses.
- **Decided before the map existed** (recorded in docs, not tickets): ADR 0002's four automation rules (ambiguous match, Jev rule, BDC cross-check, W7 = system QA); claim status `pending|accepted|rejected|retracted` + `rejection_reason`; ingest item `result` + `candidates`; `review_items` dropped (evidence_layer_plan.md §4); the BDC parser is the only source of SoI `lends_to` claims (build_roadmap.md Step 21); authorship overhaul (decisions.md §13).

## Decisions so far

- [RawDocument shape](issues/01-rawdocument-shape.md): one document per citable row; `url` required; storage computes sha256; `content: bytes` never crosses Celery; bulk row = header + row bytes; PDF raw_text written once; free-dict meta; frozen.
- [Research: Form 5500 bulk data contents](issues/05-research-form-5500.md): **no per-plan fund lineups in bulk data** (line 4i schedule is a per-filing attachment, no bulk/API); large plans give asset-class $ totals + Schedule D pooled vehicles (CCT/PSA/MTIA/103-12) by EIN; small plans totals only; plan key EIN+PN; no DOL sponsor index (buildable); amendments replace filings with new ACK_ID.
- [Research: Press-release and news feed sources](issues/10-research-press-feeds.md): PR Newswire + GlobeNewswire public RSS (20 summary items/feed, M&A and Dentistry feeds exist); Business Wire and ACCESS block `/rss` in robots; **Google News RSS is blocked** (robots, ToS, personal-use-only notice); wire terms ban scraping/database storage (legal call for the developer); wire datelines survive republication — a syndication signal.
- [Research: Google Places terms, pricing and a free geocoder](issues/09-research-places-geocoder.md): ADR 0003 holds — only `place_id` may persist (lat/lng ≤30 days; no names/addresses/phones); Text Search (New) with name/address is $0.032/call (IDs-only is free), not $0.017; Places coords can't feed a non-Google map; US Census Geocoder is free/public-domain but approximate and weak on commercial addresses; Nominatim is ODbL and rate-limited.
- [Research: EDGAR access, BDC identification and SoI formats](issues/08-research-edgar-bdc.md): BDC filings are **HTML, not PDF**; Schedules of Investments are **Inline-XBRL tagged per holding since 2022/23**, and SEC DERA publishes a monthly BDC dataset (`soi.tsv`, ~122k holdings, 165 BDCs) — borrower names mostly buried in free-text identifiers; HTML parsing still needed pre-2022 and for JV exhibits; BDCs found by `814-` file number (no SIC), ~171–187 not ~150; SEC UA + 10 req/s; full-text search JSON is undocumented.
- [Research: Form ADV and IRS exempt-org bulk data](issues/07-research-form-adv-irs.md): monthly SEC adviser files give `Any PE Funds` per adviser (ADR 0001's `pe_firm` test, current to 2026-10); fund-level rows (name, `805-` id, `Fund Type` = "Private Equity Fund", fund→adviser link) only in the historical archive through 2024 — post-2025 funds only in per-adviser IAPD PDFs; PE/VC split matches the form; absence from ADV ≠ not PE (family offices, state advisers missing); IRS EO BMF gives exempt status by EIN, not ownership (only Form 990 Schedule R names controlled entities).
- [Docs governance and definition of done](issues/02-docs-governance.md): precedence ADRs > GLOSSARY > spec > decisions.md > CLAUDE.md > docs, every conflict to the developer; roadmap archived when the spec lands; PROGRESS.md deleted; study notes + primer archived; evidence_layer_glossary = sources/tools reference; done = real fixtures + recorded live lookup + BDC XBRL cross-check + developer commit; doc-digest retired, other skills reframed.
- [What a business entity is](issues/12-what-a-business-entity-is.md): `business` and `rollup` replaced by `brand`, `company`, `location` plus a `family` owner node ([ADR 0005](../../docs/adr/0005-brands-companies-locations-separate.md)); a location keeps its identity across operators; identifiers and addresses in their own sourced tables (closed scheme list, strong IDs unique); canonical name ranked by code; **industry** is the shared line-of-business term, assigned by code, never a claim.
- [Schema conventions](issues/04-schema-conventions.md): internal bigint keys + opaque `public_id` on entities and documents; enums as text + named CHECK with a drift test; references are FKs or join tables (`edge_claims`, `ingest_item_candidates`), never ids in JSONB; no deletes on evidence tables; ingest items come only from operator batches (`stage` dropped, `failed` = resolution errors). Also ruled: **no on-demand research**, misses go to a demand log ([decisions.md §15](../../docs/decisions.md)).
- [Claim producers and the claims door](issues/17-claim-producers-and-door.md): the door is an in-process function (no `POST /internal/claims`); four producers (`llm` default, `parser`, `etl`, `selector`), all quoting stored documents and passing `verify_citations`; a quote rule per document kind (store-locator JSON as one code-rendered record per document); **identity records** replace hints; `producer` + `producer_version` on claims and sourced identity rows; code producers run a shape check first and alert on failures; one transactional, idempotent call per producer run.
- [Predicate semantics](issues/15-predicate-semantics.md): claims read subject → object under a role table of allowed entity types (mismatches rejected); `operates_location_of` renamed **`operated_by`** (location → company); `acquired_by` and `owned_by` back one ownership hop; a brand's owner may be named directly (ADR 0005 amended); a location's brands are `location_brands` identity rows, never a hop, which gives the franchise rule its two verdicts; `holds_position` = BDC equity rows; licensing and BDC fund totals stay out of v1; glossary **Operator**.
- [Entity lifecycle: status, merges and renames](issues/13-entity-lifecycle.md): status `active|merged|closed`, set only by code; a merge adds a `merged_into_id` pointer and rewrites nothing (older entity survives, old URL redirects, undoable); only code merges (two strong identifiers on two same-type entities, a verified rename, or resolution rules), no hand merge (ADR 0002 amended); `renamed_from` has no object and feeds a former-name alias; identity rows keep history and gain `retracted_at`, set only by withdrawing a whole producer version; only `company` → `investment_firm`/`fund` type changes, on a Form ADV match.
- [Claim identity and resolving extracted names](issues/18-claim-identity.md): the LLM returns the **name as written** for each side, never an id; claims store `subject_name`/`object_name` and the door resolves them in the same call (ids are the resolver's current answer, re-resolvable with an events row); no match creates a `company` (or a `family` when the LLM marks a person or family), ambiguous leaves the id null and retries (ADR 0002); `claim_hash` covers names, predicate, document and quote, never ids; `quote_start`/`quote_end` replace `quote_offset`.
- [ExtractedClaim and the extraction result envelope](issues/21-extractedclaim-and-envelope.md): the response is only `claims: list[ExtractedClaim]`; code gives each read document no claim cites `no_evidence_found` (the only spelling), and only from a response that finished; an unreadable filing or failed response is a failure, never "no evidence" (ADR 0002 corrected); fields `subject_name`, `subject_is_family`, `predicate`, `object_name`, `object_is_family`, `document_label`, `verbatim_quote`, `event_date` (+ `event_date_precision`), `value`; bad items are dropped, bad responses retried.
- [Claim value schemas and values over time](issues/16-claim-value-schemas.md): one value model per predicate; ownership carries `stake_pct`/`stake_type`/`stake_basis`, and `acquired_by` gains `deal_status` (only `completed` backs a hop, so announced deals are pending deals); BDC rows follow the SEC tags (amounts in full units + `currency` + `scale`, `affiliation`, period-end date); values over time are new claims, never edits, and the edge shows the newest by as-of date; a BDC is a `fund` with an `814-` number.
- [Owner kind: storage, evidence and the PE-firm test](issues/14-owner-kind.md): `owner_kind_evidence` rows, with code computing `entities.owner_kind` and its confidence; Form ADV `Any PE Funds = Y` is rank 1 for `pe_firm` and `N` proves nothing (ADR 0001 amended); the LLM quotes owner descriptions and a term table in code maps them (unknown phrases go to an operator report); BDCs are `other_investment_fund`; new kind `cooperative`. Split off: "Funds and their investment firm".
- [Funds and their investment firm](issues/65-funds-and-their-investment-firm.md): new predicate **`managed_by`** (fund → investment_firm), never a hop, one manager at a time; the chain stops at the first PE fund or firm, and a fund and its firm count as one PE owner (row keyed to the firm); a fund's own Form ADV type is rank 1, else it takes its firm's kind; `pe_firm` renamed `private_equity`, new kinds `real_estate` and `venture_capital` (ADR 0001 amended); one firm entity holds all its adviser registrations, a listed parent stays a separate company; the role-table check moves to edge building. Also ruled: **housing** is its own parked effort ([housing map](../housing/map.md), ADR 0004 amended).
- [Conflict, succession and co-investors](issues/25-conflict-succession.md): a hop ends only when a source names that owner as seller or exit (`owned_by` with `holding: former`), a completed acquisition states a stake that can't be true beside it, or 18 months pass unconfirmed; any other overlap is **co-ownership**; a conflict is stated stakes that can't all be true (ADR 0001 and 0002 amended); edge confidence gains `sources_disagree`, and the category is `sources_disagree` only when readings differ; undated claims never restart a hop a dated claim ended; `deal_status` gains `terminated`; the newest stake decides control; `operated_by` and `managed_by` hold one at a time.
- [Category precedence and public companies](issues/27-category-precedence-storage.md) (formerly "Category precedence and storage"; storage split off to "Category storage and recompute"): a brand, company or location carries a category, launch computes brands only; PE control, then PE minority, then co-owners by stated stake or a fixed order; a controlling owner of unconfirmed kind gives "owner type not confirmed" unless confirmed PE exists; a public company is PE-owned above 50% of voting power, and PE minority stake only from a 13D or a 13G not filed under Rule 13d-1(b) (ADR 0001 amended); voting stake first; shortest degree per PE owner; verified when one chain is fully verified.
- [What "checked" means and coverage states](issues/28-checked-and-coverage-states.md): an entity is checked when every source the product requires for it has finished a run, dated by the oldest run; only PE-owned and PE minority stake show before that, everything else reads **`not_yet_checked`** (ADR 0001 amended); `document_reads` (cited, no evidence, unreadable, claims rejected) and `source_runs` store the outcomes; shared sources count through their latest complete pass; withdrawn producer versions withdraw their reads; no engine coverage states; edge confidence drops `estimated`.
- [Document storage, fetch log and last-confirmed](issues/20-document-storage-fetch-log.md): one document row per URL and extracted text (bytes once at `documents/{sha256}`, plus `domain`, `published_on`, `last_seen_at`); a same-text re-fetch or `304` advances `last_seen_at`, and last-confirmed follows it; a changed text is a new version the LLM re-reads whole; a `fetches` log kept 90 days; parents hold original bytes and children (Schedule rows, locator records, bulk rows) carry their own `raw_text`; keep all visible text, PDF page markers, versioned extractor; S3 write-once with object lock in production.
- [Edge lifecycle: ending, retraction and staleness](issues/26-edge-lifecycle.md): one edge row per ownership period, changed in place with events; phases `pending|active|unconfirmed|ended` with end reasons (only real endings feed "formerly PE-owned"); retraction follows claims, never direct, so nothing resurrects; one withdraw command per producer version; a clean Schedule missing a loan ends it; ownership never ends by absence; 18 months unconfirmed is `unconfirmed`, not ended; `expected_close_text` maps to a closing range on pending deals for faster fetches near closing. Recompute mechanics moved to "Category storage and recompute", concurrency to "Celery topology".
- [Category storage and recompute](issues/68-category-storage-and-recompute.md): categories are stored in `entity_categories` (one current row per brand, events only on category or confidence change) and PE owners in `entity_pe_owner_periods` (one row per brand, PE owner and period; ended rows are the formerly-PE history); chains are walked on read; recompute runs owner kinds, then touched edges, then every brand below the change, in chunked Celery tasks; a nightly drift check recomputes everything and alerts on any difference.
- [Brand card, receipt and edge shapes](issues/39-card-and-graph-shapes.md) (formerly "Claim card and graph output shapes"; graph and non-brand shapes split off to "Graph endpoint and non-brand output shapes"): **brand card** and **receipt** replace "claim card"; the card's nine sections, each shown only when non-empty; the walk branches at every owner, so every PE owner on its own path shows with its degree, and a firm's own owners are labels; receipts show quote, source, live link and dates, never a re-served archive copy except official row text, and no reader label; passive 13d-1(b) holdings never show.

Local-only decisions (NPPES research, launch states, SoS and vet boards) moved to the [local-businesses map](../local-businesses/map.md) on 2026-11-04.
