## Question

How does extraction run: per document or per entity, Batch API vs synchronous, which models and when to escalate, what goes in a request, chunking and caching, failure handling, re-extraction, and what it costs?

## Context

- **Batch vs sync**: A2 must be synchronous; Batch API results are async (most within 1h, max 24h), arrive in any order and can expire — seeding needs submit → poll → resume; a blocking `retrieve → extract → verify → publish` chain can't wait on it.

Batches; native citations can't combine with `output_config.format`; sampling params may 400 on recent API versions → cache key (sha, prompt_version, model).

- **Chunking & prompt-cache layout**: chunk size/overlap, quotes crossing chunk boundaries, stable cached prefix.
- **Failure handling**: ">5% malformed → batch flagged" (research_flows.md:65) — under ADR 0002 "flagged" must mean an operational alert / halt / retry; also `refusal` and `max_tokens` stop reasons.
- **Re-extraction policy** when prompt or model changes.
- **Cost figures disagree**: evidence_layer_plan.md:229 (cents to tens of cents per entity; "real money at 100k") vs decisions.md:89 / pre-launch-seeding.md:102 (low hundreds total; the latter still counts BDC parsing as LLM cost) vs research_flows.md:18 ("a few dollars" for national roster seeding).

## Answer

Resolved 2026-11-15 in a grilling session over two days (three rounds; tests of Haiku 5.5 and DeepSeek through OpenRouter, a brand-line check, and DeepSeek against Qwen3.8-27B; all recorded under Comments and in [extraction-model-comparison](../research/extraction-model-comparison.md)). Test spend in this ticket: about $24 on OpenRouter, $1.40 on DeepSeek.

- **Model:** DeepSeek V4.1 Flash on DeepSeek's own API, called with httpx; JSON mode with the schema in the system prompt, every item validated on its own; thinking on; no batch; no escalation tier (CLAUDE.md "Opus-class for conflicts" removed). Fallback, only when DeepSeek's API is unavailable: DeepSeek 1017 through OpenRouter on DeepInfra, InferenceNet or CoreWeave. Haiku and Qwen not used. Data terms accepted: DeepSeek's own API may train on inputs and stores them in China (inputs are public documents and the prompt). Why: under production conditions (no brand named, v8 prompt, 157 documents, two runs) DeepSeek found 141 and 142 of 218 known facts against Qwen's 129 and 133, both 92.5% fully correct blind, DeepSeek with no lost answers and 71% run-to-run agreement (Qwen 3 lost, 53%), at a tenth of Qwen's cost ($0.0044 a document) and a sixth of its time. Haiku's apparent portfolio-page failure came from the test's brand line; its testing was stopped at the developer's request.
- **Request:** one document per request; no brand, entity or registry data; no document label (`document_label` dropped from ExtractedClaim and owner descriptions; corrects "ExtractedClaim and the extraction result envelope"). A document version is read once per producer version. Up to 200,000 tokens whole; longer in windows of up to 150,000 tokens at block line breaks with 2,000 tokens of overlap; quotes checked against the whole stored text; the read's outcome set when every window finished, one failed window making it `unreadable`. System prompt first, document last (DeepSeek's automatic prefix cache).
- **Versions (corrects "Claim producers and the claims door"):** an LLM `producer_version` is the prompt version plus the model name sent (`p8/deepseek-flash`); `extraction_model` is the name returned, with an alert if it changes under the same sent name; fallback reads carry their own name (`p8/deepseek-v4.1-flash-1017`).
- **Failures:** a failed response is an HTTP error or timeout, an output-limit stop, empty content, a refusal or content filter, or JSON that doesn't parse into the envelope. Three attempts with backoff; an output-limit stop split in half once; after three availability failures (server error, rate limit, timeout, payment error) one try through the fallback; then `unreadable`, an alert, and the source run stays incomplete. A daily sweep retries `unreadable` reads of the current version for 7 days. Output limit 120,000 tokens; 15-minute timeout.
- **New versions (corrects "What 'checked' means and coverage states" and "Edge lifecycle"):** a new prompt or model version re-reads every document older versions read, queued when it ships, under the spend cap. A finished new read supersedes the older version's read of that document and retracts claims only older reads found; a failed new read leaves the old one standing. New table `claim_reads` (claim, document read): a claim is retracted by supersession or withdrawal only when no non-retracted read found it, so the withdraw command's step 1 keeps claims another live read found and a fix can run before the withdrawal.
- **Records:** new table `extraction_requests`, one row per API call (document, window, version, model sent and returned, host, attempt, status and failure reason, finish reason, tokens, seconds, time); the raw response written once to S3 `extraction-responses/{id}.json` and kept for good; claims gain `extraction_request_id`; each call's cost is one `api_costs` row. No extraction-cache or batch tables.
- **Timing:** bulk work (first seeding pass, version re-reads, the daily sweep) waits for DeepSeek's off-peak hours; single new documents go at once.
- **Re-reads:** a registry `portfolio` page whose answer has no claim naming its owner is read once more, both answers' claims kept (triggered by code from the registry role). A second read of every document (about 5% more known facts, double cost) is revisited with production numbers.
- **Checks:** a weekly golden-document check alerts when answers drift (the only sign of a silent change behind DeepSeek's moving `deepseek-flash` name).
- **Cost:** measured about $0.0044 per document off-peak, $45 to $54 per 10,000 documents; replaces the conflicting estimates in the docs.
- **Split off:** [Extraction prompt rules](77-extraction-prompt-rules.md) (v5 vs v8, trademark notices and licensed brands, the "Prior to <firm>" exception, the precision judge's notes, a full-run check before adoption).
- Docs: CLAUDE.md (stack line, cost-logging line); evidence_layer_plan.md (Stage 3 rewritten; §4 `claims` producer_version and `extraction_request_id`, `document_reads` supersession, the withdraw command, new `extraction_requests` and `claim_reads`; table pointer; cost controls); research_flows.md Step 4 and cost line; decisions.md and pre-launch-seeding.md cost lines; build_roadmap.md Step 7. No ADR: a model change is a new version re-read for about $50 per 10,000 documents.

Handed on:

- "Operational identity, budgets and guardrail values": thresholds for the failure-rate and dropped-item alerts and the weekly golden check; the spend cap on version re-reads; balance and key-limit alerts for DeepSeek and OpenRouter (a key's own limit stopped this ticket's test); `api_costs` rows per extraction call.
